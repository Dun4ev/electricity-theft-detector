# EnergyGuard AI: Система выявления краж электроэнергии

Данный файл содержит полную историю проектирования, концептуальные схемы, выводы исследования и технические спецификации, сформированные в ходе обсуждения проекта. Сохраняйте этот файл в папке проекта для дальнейшего разбора и презентации.

## 1. История обсуждения и ключевые выводы

### Постановка задачи
**Цель**: Разработать систему контроля электроэнергии для локализации коммерческих потерь (Non-Technical Losses, NTL) и обнаружения краж (набросов на линию, шунтирования счетчиков) на уровне сети низкого напряжения (0.4 кВ) по цепочке: *Подстанция -> Локальный трансформатор (ТП) -> Распределительные линии -> Конечные потребители*.

### Ключевые выводы исследования
1.  **Коммерческие потери (NTL)** — это воровство электроэнергии, утечки из-за износа или некорректная работа приборов учета. В современных сетях они выявляются путем автоматического почасового сопоставления отданной энергии и суммы показаний клиентов.
2.  **Диспетчеризация (AMI)** — основа решения. Умные счетчики должны передавать данные регулярно (каждые 15–60 минут), чтобы аналитическое ядро могло строить точные балансы.
3.  **Локализация краж** без установки датчиков на каждом столбе возможна с помощью **машинного обучения (Machine Learning)** и **анализа падения напряжений**.

## 3. Спецификация оборудования для MVP

Мы выделили два подхода к аппаратному обеспечению системы:

### А. Реальный пилотный стенд (Промышленный уровень)
*   **Балансовый счетчик (на ТП)**: *Меркурий 234 / 236* (3-фазный, с интерфейсом RS-485 или GSM-модемом). Фиксирует суммарный профиль мощности.
*   **Счетчики клиентов**: *Меркурий 206* или *Миртек-12-РУ* (1-фазные, со встроенными радиомодемами RF 433/868 МГц или LoRaWAN).
*   **Концентратор (УСПД)**: Промышленный контроллер *Wiren Board 7* или *УСПД Меркурий 250* для опроса приборов и отправки данных на сервер по MQTT.

### Б. Лабораторный прототип (Настольный уровень)
*   **Мозг системы**: Микроконтроллер *ESP32* или плата *Raspberry Pi*.
*   **Сенсоры тока**: Неинвазивные трансформаторы тока *SCT-013* (надеваются поверх изоляции фазного провода).
*   **Сенсоры напряжения**: Прецизионные модули *ZMPT101B*.

## 4. Программно-алгоритмический стек

Для быстрого развертывания минимального MVP выбран следующий проверенный стек:

*   **База данных**: **PostgreSQL + TimescaleDB** (для эффективного хранения временных рядов показаний приборов учета с возможностью реляционного описания топологии сети).
*   **Сбор данных**: Протокол **MQTT** (брокер *Eclipse Mosquitto*).
*   **Серверное API**: **FastAPI (Python)**.
*   **Машинное обучение и Аналитика**:
    *   `Pandas` и `NumPy` — для выравнивания временных интервалов и расчета физического баланса энергии.
    *   `scikit-learn` (алгоритм **Isolation Forest**) — для автоматического поиска аномальных профилей потребления клиентов без предварительной разметки обучающей выборки.
*   **Дашборд**: **Streamlit** (позволяет быстро написать красивый веб-интерфейс на чистом Python) или **Grafana**.

## 5. Инструкция по запуску интерактивного симулятора

В папке проекта находится готовый демонстрационный симулятор баланса:
1.  Откройте файл `index.html` в любом современном браузере.
2.  Перейдите во вкладку **«Интерактивный Симулятор»**.
3.  Вы можете изменять нагрузку честных пользователей кнопкой **«Изменить нагрузку»**.
4.  Включите чекбокс **«Активировать наброс»** или подвигайте слайдер **«Симулировать хищение (кВт)»**, чтобы сымитировать кражу в обход приборов учета.
5.  Система мгновенно пересчитает баланс на ТП и выдаст статус тревоги `🚨 КРАЖА ОБНАРУЖЕНА!`, продемонстрировав физический принцип работы MVP.
