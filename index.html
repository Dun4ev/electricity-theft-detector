Сквозной контроль сети 0.4 кВ

MVP выстраивает четкую иерархию баланса энергии. Подстанция измеряет общий отпущенный объем, а умные счетчики потребителей сообщают о детальном потреблении каждые полчаса.

Ключевые преимущества архитектуры:

  • Автоматический сбор (AMI): Данные передаются без участия человека через GSM или радиоканал.
  • Мгновенное обнаружение: В отличие от ежемесячных сверок, MVP выявляет воровство за считанные часы.
  • Минимизация ложных тревог: Математическая модель динамически учитывает нагрев проводов и нагрузку на линию для расчета физических потерь.

Интерактивная архитектурная схема сквозного контроля и выявления коммерческих потерь

Оборудование для MVP

Для запуска прототипа не нужно покупать дорогое зарубежное оборудование. Мы предлагаем надежные Российские решения с интерфейсами удаленного опроса.

Где ставится Модель прибора Интерфейсы
На подстанцию (ТП) Меркурий 234 / 236 RS-485, CAN, GSM-модем
У абонентов Меркурий 206 / Миртек Радиоканал (RF), PLC, LoRaWAN
Сборщик (УСПД) Wiren Board 7 / Меркурий 250 RS-485, Wi-Fi, Ethernet, GSM

💡 Лабораторный лайфхак для MVP:

Для первых тестов "на столе" можно использовать микроконтроллер ESP32 стоимостью ~6 € и 2-3 датчика тока SCT-013 для имитации трех потребителей.

Интеллектуальный анализ и ML-стек

Сбор показаний — это лишь полдела. Главную ценность несет алгоритмический слой на Python, который отсекает случайные помехи и выявляет хитрые схемы краж (например, периодическое шунтирование).

📊

Расчет физических потерь

Алгоритм рассчитывает технические потери в проводах по закону Джоуля-Ленца, учитывая сопротивление ЛЭП и суммарную нагрузку, чтобы исключить ложные срабатывания.

🌲

Isolation Forest (ML)

Обучение без учителя из библиотеки Scikit-Learn. Идеально находит «аномальных» потребителей, чьи профили нагрузки резко выбиваются из массы соседей.

📉

Анализ корреляций

Оценивает связь между колебанием напряжения на фазе ТП и потреблением абонента. Если напряжение проседает, а счетчик абонента этого «не видит» — фиксируется кража.

Минимальный стек разработки ПО для MVP:

# База данных: PostgreSQL + TimescaleDB (для хранения графиков нагрузок)
# Аналитика: Python (Pandas, Numpy, Scikit-learn)
# API & Сбор данных: FastAPI + Eclipse Mosquitto (MQTT)
# Дашборд: Streamlit (быстрый UI на Python) / Grafana

Готовые сценарии реализации и подбор оборудования

Мы подготовили 3 готовых варианта реализации системы разного масштаба и бюджета: от лабораторного макета до масштабируемого промышленного решения на LoRaWAN.

ЛАБОРАТОРНЫЙ

1. Прототип "На столе"

Для быстрой и дешевой проверки гипотез и отладки бэкенд-алгоритмов без покупки дорогостоящих приборов.

Что нужно сделать:

  • Развернуть Docker с PostgreSQL + TimescaleDB и Eclipse Mosquitto.
  • Собрать схему на ESP32 с 2-3 датчиками SCT-013.
  • Написать прошивку для отправки данных по MQTT в базу.

Необходимые компоненты:

🧠 Микроконтроллер ESP32 NodeMCU ~7 € 🔌 Датчик тока SCT-013 (30A) ~11.5 € (х3) ⚡ Датчик напряжения ZMPT101B ~5 €
ПИЛОТНЫЙ

2. Промышленный пилот (СНТ)

Для развертывания в реальном поселке или СНТ на базе сертифицированного оборудования Российского производства.

Что нужно сделать:

  • Установить балансовый счетчик Меркурий 234 в шкафу ТП.
  • Заменить счетчики абонентов на Меркурий 206 с RS-485 или RF.
  • Установить контроллер Wiren Board 7 для сбора данных по RS-485.

Необходимые компоненты:

📊 Балансовый счетчик Меркурий 234 ~145 € 🏠 Абонентские счетчики Меркурий 206 ~43 € (хN) 🧠 Контроллер Wiren Board 7 (УСПД) ~290 €
МАСШТАБИРУЕМЫЙ

3. IoT-решение на LoRaWAN

Для крупных объектов и городов. Счетчики передают данные на километры напрямую на базовую станцию без промежуточных шлюзов.

Что нужно сделать:

  • Установить уличную базовую станцию LoRaWAN в центре объекта.
  • Монтировать интеллектуальные счетчики с поддержкой LoRaWAN.
  • Настроить парсинг данных из LoRaWAN Network Server в TimescaleDB.

Необходимые компоненты:

📡 Базовая станция Вега БС-3 (LoRaWAN) ~550 € ⚡ Счетчики Миртек-12-РУ LoRaWAN ~73 € (хN) 🔌 3-фазные счетчики Фобос 3 LoRa ~115 €
